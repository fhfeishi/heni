# ADR 0005 — 音量偏好由 Rust 成组恢复与提交

日期：2026-09-03
状态：当前切片已采纳；拖动中实时试听与 Flutter 的差异未获批准

## 问题

音量和静音原来只在运行时保存。重启后丢失静音，或先加载媒体、再从前端异步恢复音量，都可能产生意外声音。把三个相关字段分开保存，也会留下“音量为零、却不是静音”等不可解释的状态。

## 决策

- Rust `PlaybackPreferences` 保存 `volume`、`muted`、`lastAudibleVolume`。前两项进入权威 snapshot；最后一次可听音量是 session 内部恢复依据，不建立另一套前端设置状态。
- 启动装配读取既有 SQLite `settings` 中的 `playback.preferences`，然后创建播放 runtime 与监控线程。首次加载媒体时已经具有恢复值，不依赖 React hydration。
- 三字段作为一个严格校验的 JSON 值，在一个事务中提交；没有新表或 schema migration。缺失键保持此前 100%／未静音默认值，不在读取时写库。损坏记录或读取失败则以 0%／静音启动，保留原记录并暴露有限错误码；用户明确调音量或静音后才修复。
- 调至零时静音并记住上次非零音量；取消零音量静音时恢复该值；调至正值时解除静音。恢复值为 1–100，故低于 1 的外部小数命令在以后恢复时至少为 1；产品滑块只提交整数。
- 音量／静音先在候选 session 校验，再保存，再调用当前引擎的无失败音量／静音原子 setter，最后提交会话。保存失败不改变输出或候选版本。其他播放命令不写偏好。
- 数据库操作不进入 CPAL 实时回调；当前在命令路径持有 controller 锁期间提交。数据库争用可能延迟命令与 monitor，尚未测量延迟上界；不宣称无卡顿。以后若 setter 成为可失败操作，必须重新设计此提交次序。
- 主窗音量手势局部预览，松开或键盘抬起时一次应用并保存；取消、失焦、卸载不提交草稿。等待时保留焦点并阻止重复提交。Mini 继续使用同一播放端口。
- 命令失败不会被后续正常位置读取立即清空。用户关闭或开始新操作后才清除；启动恢复警告可关闭，原始路径／数据库诊断不进入 UI。

## 取舍与未完成项

不增加单独的“预览音量”协议、客户端持久化或通用偏好管理器，避免两个可变音量来源和每个移动事件写库。代价是本切片拖动时不实时改变声音，与 Flutter 不完全等价。此差异必须继续补齐或取得用户明确批准，不能仅凭本 ADR 写成“批准差异”。

隔离测试覆盖数据库重开、缺省不写入、损坏数据保留、事务失败、引擎不变、首次加载恢复，以及主窗草稿／取消／连续键盘／卸载。真实重启、Mini 和声音听感按发布记录单独验收；无音频播放的界面测试不证明听感。
