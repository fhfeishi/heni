# ADR 0006 — 把阻塞工作与客户端生命周期分别处理

日期：2026-09-03
状态：播放、设置与曲库 I/O 入口已落地；原生交互和平台入口待继续验收

## 决策

播放 snapshot、poll、dispatch 与 settings snapshot、update 使用 `async` Tauri command，并显式进入 `spawn_blocking`。AppHandle 在闭包内取得既有 runtime，不克隆数据库连接或播放状态。现有 repository／controller 锁继续定义一致性边界；授权校验、音量事务和有限错误语义不变。

只添加 `async` 不能使内部同步文件／数据库调用成为非阻塞 I/O；不能把它们长时间放在异步执行器线程。五条入口均实际使用各领域内很小的工作函数，六项测试验证线程切换、错误保留和异常隔离。[Tauri 官方说明](https://v2.tauri.app/develop/calling-rust/#async-commands)

读取入口也必须移出窗口线程：如果只移动写入，主线程中的 snapshot 仍可能等待该写入持有的锁。实时音频回调不受此次 I/O 调度变更影响；音量写入期间 monitor 仍可能等待 controller，未宣称消除了所有延迟。

客户端回归全绿后，曲库的 12 条 I/O 入口接续采用同一规则：snapshot、选中文件导入、重新定位、媒体详情、旧库检测/导入和五种歌单写入，以及目录扫描。原来在异步执行器上阻塞的扫描与 ffprobe 也进入阻塞工作池。原授权、路径检查、备份、事务、批次和 Channel 规则保持；取消入口只查询短时注册表并设置原子标记，不等待 repository 锁，仍保留同步响应。

TypeScript 曲库在后台范围扩大前先补齐连接、重入和扫描生命周期。每次连接只接受一项未结束的曲库 mutation；晚到结果不能更新旧界面或触发后续成功动作；初始化读取、旧库检测与导入成功状态分别合并。扫描取消针对原端口和真实 scan ID，终止事件与命令完成不是同一概念。

## 非目标与后续门槛

这不是通用任务调度器、全局 store 或数据库重写。播放/设置 5 条加曲库 12 条入口已经迁移，但尚未进行新产物实机交互、慢盘、取消延迟或吞吐测量。Windows 文件定位仍含同步曲库查询；其 Shell/COM 线程规则和窗口操作应独立审查，不机械套用此工作池。

UI 控件禁用用于反馈，同步 ref 用于防重入；二者不能互相替代。Rust 事务成功后，前端卸载只会忽略显示结果，不撤销已提交数据。真正取消仅应用于已有支持取消的扫描任务。

验证包括 9 项 Rust 工作边界测试、14 项曲库 Hook 生命周期回归和 3 项组件检查。Windows 卡顿、设备、长时性能和真实数据异常不由这些测试替代；具体产物与未执行项以 release-evidence 为准。
