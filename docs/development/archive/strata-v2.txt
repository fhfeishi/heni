二、审计结论

2.1 总体判断

当前 Heni 的顶层设计是合理的，结论是“继续演进，不重新换架构”。正确的核心包括：

- 仓库根只有一个在建应用，Flutter v1 完整保存在 legacy/v1-flutter；
- React/TypeScript 负责界面、展示投影、交互用例和运行时契约；
- Rust 负责权威播放会话、音频资源、SQLite、扫描、元数据和 Windows 能力；
- src/infrastructure/tauri 是前端唯一 Tauri API 边界；
- IPC 输入由 Zod/serde 校验，错误使用有限 code，不把底层诊断直接显示给用户；
- 播放队列和状态由 Rust 持有唯一真相，generation/sequence 防止迟到结果覆盖新状态；
- SQLite schema、migration 和事务留在 Rust；
- 没有为了形式引入 workspace、通用 repository 基类、事件总线或万能全局 store；
- Rust lib.rs 保持为小型装配根，没有发展成参考项目中的巨型入口文件；
- capability 和 CSP 保持收敛。

这些边界不得因 UI 重建而倒退。

2.2 当前需要修正的顶层问题

以下是第二阶段的真实工程债，不允许继续用“Phase 已完成”跳过：

1. App.tsx 曾同时承担依赖装配、导入文件、扫描目录、重新定位、跨 feature 错误恢复、
   视图选择和视图渲染。S2-1 已先把文件/目录导入收敛到 useLocalImportWorkflows；重新定位
   与错误恢复仍需按真实用例审查。拆分继续以变化原因为依据，App.tsx 保持清楚的
   composition root。
2. 原 global.css 的约 2,100 行混合职责已在 S2-1 收敛为有序 CSS 入口：tokens、base、shell、
   now-playing、queue、library、playlist、playback、feedback 和 responsive。主题定义只在
   tokens.css；不得在功能样式中重新复制主题变量，也不因此引入 CSS-in-JS 或大型 UI 框架。
3. Rust 的 library/repository.rs、playback/session.rs、legacy_import.rs 和 native.rs
   是职责审查热点。只在它们混合两个独立变化原因时拆分，不按机械行数切碎。
4. settings 与 library 分别持有同一 SQLite 文件的连接是可接受的 SQLite 模式，但
   数据库打开参数、migration、busy timeout 和错误映射必须只有一个明确来源；不得让
   每个新 feature 复制一套数据库初始化逻辑。
5. S2-3 已建立 playback clock seam、有界局部插值和 300ms 条件读取：稳定状态不再传输
   全队列，状态变化返回完整快照；每帧时间不进入 React 全局状态。位置采样与状态版本
   已分离，原生 position event、订阅生命周期和跨通道采样顺序仍需单独实现/验收；不能
   把减小载荷说成减少 IPC 次数，也不能把条件读取误标为事件推送完成。
6. 初审曾发现 architecture.md 仍把主题描述为会话状态，而代码已经加入 SQLite settings；
   S2-0 已修正文档，S2-1 继续同步启动/样式与发布证据。每个切片必须保持代码、测试、
   架构和 Strata 进度一致。
7. 不强制引入 Zustand。当前局部 Hook 和纯投影是更小的方案；只有同一客户端状态确实被
   多个远距离消费者共享且 props/Context 已形成负担时，才建立窄而明确的 Zustand store。
8. 不强制引入 React Router。Heni 当前四个工作区没有 URL、历史栈或深链接需求，字符串
   联合视图足够。出现第二个真实导航需求时再引入路由。

2.3 本次审计发现并已在 S2-0 关闭的红色基线

2026-09-03 首次重新检查时：

- pnpm lint 通过；

  在 exactOptionalPropertyTypes 下把必填字段推导为可能 undefined；
- Vitest 观察到 3 个 App 集成测试失败，症状集中在 settings hydration 期间主操作被禁用

三、Museek 顶层设计研究结论

研究对象：https://github.com/aeroray/Museek
本地只读快照：research/upstream/Museek
固定提交：83c547df1525a7a2b6de66f5151b458a1abe04fb
许可证：MIT

Museek 是值得尊重的成熟 Tauri 音乐产品，但 Heni 只借鉴经审计的原则，保持 clean-room
独立命名、独立实现和独立测试。

3.1 应借鉴

- App 只声明路由和全局产品入口，RootLayout 固定组合侧栏、TopBar、Outlet 和 PlayerBar；
- 主内容切换时播放器和队列外壳保持稳定，音乐产品不会因页面导航重建播放核心；
- AppInit 明确表达设置、来源、下载、曲库、Open With 和播放恢复之间的启动顺序；
- main.tsx 能按窗口角色选择不同根组件，说明多窗口不是在单个页面里堆条件分支；
- playback/clock.ts 把平滑播放时间做成独立订阅缝隙，UI 不直接抓取底层音频对象；
- 通知、Play All 等窄端口避免 store 互相反向导入；
- Mini Player、系统媒体控制、防休眠、托盘、自动更新、NSIS/DMG 和数据备份形成完整的
  桌面产品发布清单；
- 缺失本地文件保留 unavailable 状态，不静默破坏用户收藏和分类。

Heni 应借鉴的是“稳定外壳 + 明确启动 + 独立播放时钟 + 发布闭环”，不是目录名称。

3.2 不得照搬

- Museek 的 playerStore.ts 约 1,033 行、localMusicStore.ts 约 1,043 行，播放、I/O、歌词、
  封面、持久化和大量副作用聚合；Heni 不得用一个 Zustand store 复刻这种复杂度。
- Museek 的 Rust lib.rs 约 1,956 行；Heni 当前 67 行装配根明显更健康，不得倒退。
- Windows 本地音频存在 fetch arrayBuffer + decodeAudioData 的整文件 WebView 解码路径；
  Heni 正式内核继续使用 Rust 原生解码/输出，Web Audio 只可作为实验对照。
- Museek 的本地曲库和多类偏好大量使用前端 JSON/文件插件；Heni 继续使用 Rust SQLite、
  migration 和事务。
- 参考快照设置 csp: null，并开放 **、HOME、Desktop、Downloads 等宽文件权限；Heni
  保持最小 capability 和结构化原生命令。
- Museek 的在线音源、下载、歌词和识曲不属于 Heni 当前产品范围。
- 不因为 Museek 使用 Tailwind、Radix、React Router 或 Zustand，就把这些依赖视为
  “现代化套餐”。只有 Heni 的真实问题证明收益时才引入。

4.1 必须继承的气质

- 全窗口只有一个全景美景背景层，贯穿顶栏、侧栏、主内容和底部播放坞；
- 深色、低眩光、带主题染色的录音室哑光/玻璃材质；
- 背景负责氛围，语义主题负责可读性和交互状态，两者不能互相替代；
- 常驻底部播放坞：左侧当前曲目，中间播放/进度，右侧队列/模式/音量；
- 桌面宽度默认展开侧栏，空间不足时紧凑化，并有迟滞避免 resize 抖动；
- 中文为默认产品语言，字体优先 Microsoft YaHei、Segoe UI 和系统 sans-serif；
- 播放页是安静的 listening console，展示可信的源文件与音频信息，不伪造音质；
- 动效克制：短 hover、平稳布局切换、缓慢背景交叉淡化，不持续漂浮或脉冲；
- Windows 最小可用逻辑尺寸 900 × 620，1180 × 760 是主要设计基准；
- 左上角品牌只显示四个小写字母“heni”。

4.2 必须修正的 legacy 缺陷

- 不复刻多层透明蒙版相乘后的灰雾和低对比度；
- 不复刻每一层、每一行都套大圆角边框的“卡片套卡片”；
- 不让大面积装饰和空白压过曲库信息密度；
- 不让背景图导致正文、路径、disabled 状态和焦点环不可辨认；
- 不让主题色以高饱和度大面积铺在文本下面；
- 不把文件路径放在比歌曲元数据更抢眼的位置；
- 不依赖单个截图的临时配色，所有主题都必须经过同一语义 token 规则。

4.3 初审时对 Tauri UI 的判断与修复追踪

初审时 Tauri UI 比早期 Flutter 版本更清楚、更克制，侧栏、主区和底栏层级已经成立；但它
仍然是工程样机，不是最终成品：

- 真实美景图片选择、授权、持久化和失败回退尚未闭环，Heni 的核心个性缺失；
- 录音室绿的默认画面过于单一，空状态占据大面积空间；
- “LISTENING CONSOLE”“LOCAL LIBRARY · SQLITE”“LOCAL FIRST”等技术英文泄漏到默认
  中文产品 UI；SQLite、runtime、schema 术语应留在诊断/开发信息中；
- 曲库空状态和空列表没有形成成熟的信息层级，真实大曲库的密度与性能还未证明；
- 设置错误通知会遮挡主要内容，错误优先级和 degraded 模式需要重新设计；
- CSS 已经难以维护，视觉改动容易产生跨 feature 回归。

修复追踪：以上保留初审事实，不作为当前未实现清单。S2-0/S2-1 已收敛设置错误与 CSS；
S2-2 已落地纯小写字标、中性唱片占位、中文文案、曲库密度和单张静态美景设置，且有
部分真实 Windows 证据。大曲库性能、全主题/图像/尺寸矩阵与空态整体完成度仍待验收；
当前结论由动态进度和发布记录限定，不能仅凭代码存在就视为产品闭环。

因此旧 task-demand 中“Phase 4 UI 核心完成”只能表示功能竖切存在，不能表示视觉验收完成。

4.4 品牌硬约束

- 窗口左上角只显示纯文字“heni”，全小写；
- 禁止圆形 H、单字母 H、单字母 h、Heni、HENI 作为应用内品牌徽标；
- 唱片或封面占位不得用单字母 H 冒充品牌，可使用中性唱片纹理、音符或封面色块；
- 不做字标发光、旋转或持续动画；
- Windows 小尺寸应用图标需要单独做光学可读性验证，但不能反向污染应用内字标规则。


五、第二阶段目标架构

5.1 依赖方向

React product shell
    ↓
feature UI + application workflow
    ↓
typed port + Zod contract
    ↓
src/infrastructure/tauri adapter
    ↓
thin Tauri command boundary
    ↓
Rust application/runtime
    ↓
playback engine | SQLite repositories | scanner | metadata | Windows platform

依赖只能向下。React 组件不得直接 import Tauri API；TypeScript application 不得直接读写
文件或 SQL；Rust 核心不得依赖 React 的 view 名称、CSS 或 DOM 概念。

5.2 TypeScript 目标结构

src/
  app/
    App.tsx                    只负责装配和稳定外壳
    bootstrap/                 只有出现真实启动顺序后建立
    workflows/                 只有跨 feature 用例需要时建立
  contracts/                  wire schema、DTO、有限错误、Port
  features/
    library/
    playlist/
    playback/
    player/
    settings/
    scenery/
    shell/
  infrastructure/tauri/       唯一 Tauri adapter
  styles/
    tokens.css
    base.css
    shell.css
    feature 样式靠近 feature 或使用清楚的独立文件

不要一次创建空目录。每次只为当前切片建立需要的文件。

跨 feature 协调应按用例命名，例如 importLocalFiles、scanLibraryRoot、recoverMissingMedia，
不得创建万能 useAppManager、GlobalStore 或 ServiceContainer。App.tsx 的目标是让读者一眼看懂
Heni 由哪些能力组成；不设置僵硬行数上限，但混入第二个变化原因时必须拆分。

5.3 启动模型

启动状态使用有限状态而不是多个互相矛盾的 boolean：

- booting：读取 runtime、settings、library、playback snapshot；
- ready：核心能力可用；
- degraded：部分能力失败，但可安全使用默认值或其他功能；
- blocked：关键数据库或播放核心不可用，显示明确恢复动作。

设置读取期间可以使用经过版本化的安全默认值，不能无理由禁用“选择文件”“进入曲库”等主
操作。迟到的读取结果不得覆盖用户已经提交的新设置。错误按影响范围显示：局部设置失败留在
设置区域；只有全局阻断才占据全局 notice。

5.4 播放状态与时钟

- Rust PlaybackSession 继续是 queue、current、status、mode、volume 和 position 的权威；
- command 处理用户意图，snapshot 处理重建，低频 event 处理变化；
- position 事件约 4–5Hz，前端 clock seam 使用 performance time 局部插值；
- seek 草稿绑定 generation，切歌后自动失效；
- 不把 currentTime 每帧写进 Zustand、Context 或 App 根状态；
- WebView reload、MiniPlayer、窗口隐藏和系统媒体控制必须共享同一 Rust 会话。

5.5 Rust 与数据库

- lib.rs 继续只做模块装配、插件和 command 注册；
- command 只做 DTO/授权校验、调用 use case 和错误映射；
- 播放实时线程不锁数据库、不分配、不记录日志、不做 IPC；
- SQLite 连接配置和 migration 有唯一入口；repository 按领域用例组织；
- 扫描在后台执行，支持取消、批次写入、背压和最终对账；
- 媒体 ID 是稳定身份，路径可重新定位，歌单和活动队列引用不被静默替换；
- settings、library、playlist 的写入继续使用事务；Partial update 必须有明确 merge 语义；
- Rust 文件拆分以职责和不变量为准，不以“每 300 行一个文件”为准。

5.6 安全

- 保持 CSP，禁止 csp: null；
- capability 默认拒绝，不开放 **、整个 HOME、Desktop 或 Downloads；
- 用户选择路径后由 Rust 复核 scope、存在性、媒体类型和稳定 ID；
- 外部程序只用结构化参数，不拼 shell 字符串；
- UI 不显示底层原始 message、完整用户路径或堆栈；
- 任何新增 sidecar、codec、系统插件和更新器必须审计来源、许可证和打包义务。


六、第二阶段产品 UI 规范

6.1 外壳

- 一个背景层、一个顶栏、一个侧栏、一个主工作区、一个常驻播放坞；
- 主视图切换不得卸载或重建播放会话；
- 顶栏左侧是 heni 和可拖动空白，中间是当前工作区/搜索，右侧是主题、设置和窗口能力；
- 当前仍可保留系统装饰。启用自定义标题栏前必须通过 Windows 拖动、双击最大化、Snap、
  系统菜单、Alt+F4、多显示器和 100%/125%/150% DPI 矩阵；
- 最大化时不得保留错误外圆角或屏幕边缘缝隙。

6.2 主题与美景

- semantic tokens 至少包含 canvas、chrome、rail、content、dock、border、hover、pressed、
  selected、primaryText、secondaryText、accent、danger、focus；
- studio/nocturne/tide 是语义主题，不允许 feature 内散落独立黑白修正值；
- 美景播放模式建议：blur 8–12px、saturation 0.78–0.88、遮罩 0.26–0.36；
- 曲库浏览模式建议：blur 14–18px、saturation 0.66–0.76、遮罩 0.38–0.50；
- 数值是审美起点，不是免测常量；最终以对比度和实机截图为准；
- 图片不可读时回退主题渐变，不出现空白、破图或全黑窗口；
- 用户必须能选择、移除和持久化美景图片，路径授权和读取通过独立 scenery port。

6.3 信息层级

- 默认中文 UI 不出现 LOCAL FIRST、SQLITE、SCHEMA、RUNTIME 等实现术语；
- 主标题、歌曲名、歌手/专辑、音频属性、路径和诊断信息按重要性递减；
- 路径默认弱化或按需展开，特殊路径仍可完整复制/定位；
- 曲库行减少边框，用 hover、selected、playing 左标记和短暂定位闪光表达状态；
- 空状态应给出下一步和必要上下文，不用巨幅装饰填满工作区；
- disabled、missing、error、focus-visible 在三套主题和美景背景上都必须清楚。

6.4 响应式

- 1180 × 760：展开侧栏、完整底栏、完整元数据；
- 900 × 620：保证所有核心操作可达，不溢出；
- 侧栏收缩使用迟滞；
- 窄宽度依次隐藏次要路径、重复标签和非关键按钮；
- 播放/暂停、进度、音量、队列和错误恢复始终可达；
- MiniPlayer 继续共享会话，尺寸、置顶和几何恢复由 Windows 实机验证。

6.5 可访问性与动效

- 键盘可完成导航、播放、seek、队列重排、dialog 和设置操作；
- dialog 有初始焦点、焦点边界、Esc 关闭和焦点回还；
- icon-only 控件必须有中文 accessible name 和 tooltip；
- 遵循 prefers-reduced-motion；
- hover 120–200ms，布局切换 220–320ms，背景交叉淡化 700–900ms；
- 不加入持续频谱、漂浮、脉冲或与播放位置绑定的背景动画。
