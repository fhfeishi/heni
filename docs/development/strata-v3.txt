一、角色、目标与规则优先级

你负责在现有 Heni 仓库中持续完成一个可靠、漂亮、易维护的 Windows 本地音乐播放器。
核心技术栈为 Tauri 2 + React + 严格 TypeScript；Rust 负责原生能力与数据可靠性。
尊重已有工程，不重启一次全量重写。专业是明确的职责、可靠的行为、细腻的界面，
不是框架数量、文件数量、功能数量或“测试全绿”本身。

需求顺序：用户最新明确指示 > 本文 > 仍有效的 ADR / 兼容约束 > strata-v2 历史。
系统与工作区安全规则始终有效。旧文档的完成记录只作证据，不自动证明当前版本通过。
本版本替代 V2 的执行优先级及冲突需求，V1/V2 文档保存在 docs/development/archive/。
参考审计见 docs/migration/strata-v3-reference-audit.md；不要每轮重复做完整参考研究。

最终体验：打开应用 → 导入本地音乐 → 找到歌曲 → 整理并播放歌单 → 切到舞台聆听
→ 查看/调整队列 → 返回原浏览位置 → 切换 Mini → 重启后保留合理设置与收藏。
过程中播放状态一致、数据不丢、错误可理解、没有意外响声，也没有突兀的命令行窗口。

三、范围与不做事项

本轮必须：本地导入与扫描、曲库搜索、个人歌单、真实播放与队列、舞台场景、
主题与基础外观设置、Mini 连续性、Windows 稳定性及可追溯发布验收。

明确不做：任何歌词展示/解析/匹配/下载/桌面歌词；账号、在线音源、抓取下载、
社交、推荐流、云同步、AI 功能、插件市场、均衡器/DSP、标签编辑器、场景编辑器。
不为不需要的歌词留占位、设置项或扩展接口。不要把舞台改成技术参数仪表盘。
自动更新、全局快捷键、托盘复杂策略等非既有必需功能先留待评估，不阻塞首个闭环。
Linux / macOS / iOS / Android 暂不实现；只保持平台边界，不预建跨端框架。

旧 Flutter 存在视频能力。不得损坏或丢弃旧视频记录，也不得将“能导入”写成“能播放”。
最新用户已明确要求支持视频，视频播放改为必须交付，不再按可接受延期项处理。
当前音频引擎拒绝视频，接入前仍须如实显示不支持并保留旧记录；不能只去掉拒绝检查。
首轮定义并验证实际可播的容器/编码组合，必须有画面与声音、暂停/定位/音量/静音、
播放结束与切换释放、音视频切换无重叠声音、失效文件/不支持编码的明确反馈。
复用现有队列与唯一播放会话；禁止独立 video 标签与原生音频同时自治播放。
视频资源仅授权当前选中/曲库确认的文件，禁止为方便直接开放任意磁盘路径；大文件须支持范围读取。
完整替代旧版前列清实际格式差异，不以扩展名或“能导入”代替解码与音画同步验收。
不因为此决策待定而停止其余音乐版本开发。

四、产品结构与行为契约

4.1 一个播放会话，两类工作空间
固定壳层由品牌/搜索/窗口操作、导航与歌单、主内容、底部播放台组成。
主内容有“歌曲”浏览与“播放舞台”两种体验；不要在现有正在播放之外再堆一个同义页面。
浏览来源是曲库、某个歌单或当前队列；展示模式是列表或舞台。两者分开建模，
切舞台不能改歌单、重建队列、重新加载当前音乐。返回保留选中歌单、搜索、排序和滚动。
页面不必全部常驻 DOM；保留必要状态即可，隐藏视图不能继续接收焦点或运行动画。
Mini 是同一播放会话的紧凑呈现，先复用当前窗口模式，不默认增加第二 WebView。

4.2 曲库、歌单、队列严格区分
曲库是已登记的媒体；歌单是持久化的有序引用；队列是当前播放会话的有序条目。
媒体稳定 ID 不等于数组下标或文件名；队列重复出现同一媒体时，条目身份必须可区分。
重定位保持引用；从歌单/队列移除不是删除磁盘文件。扫描不得擅自删收藏或更换当前队列。
导入不自动响起；重复导入可预期，取消只停止后续工作，已提交批次按既有规则保留。

歌曲浏览单击负责选择，明确播放按钮/双击负责播放；菜单动作不得冒泡触发播放。
“播放歌单”使用其完整有序内容；“播放搜索结果”若提供，必须命名清楚，不能暗中混用。
“下一首播放”在当前项后插入；“加入队列”追加末尾；改变浏览/排序不暗改播放队列。
替换正在播放的队列沿用已有保护规则，操作前说明影响，不重复弹无意义确认。
空队列、移除当前项、重复项、最后一首、单曲循环、列表循环、随机前后切换，
必须有明确规则和测试；随机不能每次渲染重新洗牌，不能死循环跳过坏文件。

4.3 歌单必须像收藏，不像数据库管理表单
侧栏可直接进入个人歌单；主区显示名称、简短说明、数量/时长及歌曲列表。
新建、改名、编辑说明、加入/移除歌曲、播放的主路径就近可达；危险操作放次级菜单。
编辑使用局部表单或对话框，不让整页常驻创建/修改表单。批量操作显示作用范围。
空歌单给一个明确的加歌入口；删除歌单不删原文件。保存失败保留输入并允许重试。
封面优先已有本地数据，没有封面时使用统一、克制的代码原生占位，不联网补图。

4.4 播放与反馈
底部播放台保持标题、歌手、播放/暂停、上下首、进度、模式、音量和队列入口。
标题优先可信本地标签，否则文件名；技术信息和完整路径放详情，不占主视觉。
保留用户主动查看/复制路径能力；日志和普通报错不泄漏完整私人路径。
进度拖动有草稿、提交、失败回退；迟到响应不能覆盖新曲目/新命令，暂停时不假走。
音量目标是拖动可试听、松开持久化，不能每个指针事件都写库。
在实现实时试听前，先定义 Rust 预览与提交边界、静音优先级、失败回退及关闭行为；
保留 volume / muted / lastAudibleVolume 一致性，坏设置不能默认满音量启动。
当前松开生效的实现只记“已有基础”，不得当作实时试听验收通过。
错误就地说明“发生什么、可做什么”，后台采样不抹掉用户刚遇到的命令错误。

五、视觉与舞台：核心交付，不是末尾美化

5.1 身份与层级
左上角只用 heni 四个小写字母，不再加入 H / h 单字徽章或 Heni/HENI。
延续深青黑、青绿种子色、柔和金色/暖色强调、通透但有实体感的表面。
首先打磨深夜主题，再验证录音室和潮汐；按用户最新反馈增加暮玫、鸢尾、余烬，
共六套协调预设，通过设置内色卡选择。新增主题同样验证文字、表面与强调态，不只换按钮颜色。
配色用语义 token：背景、表面、悬停、选中、文本、强调、焦点、危险。
主内容清晰、曲名突出、次要信息安静。减少卡片套卡片、粗描边、巨型标题及大面积灰雾。
统一全局背景和局部遮罩，玻璃只在需要分层处使用，不把每个列表项变成磨砂卡片。
正常文字对比度以 4.5:1、大字和关键图形以 3:1 为验收目标；亮图与深图均检查。

5.2 舞台与场景
舞台展示当前歌曲和沉浸画面，不是另一份曲库、队列或歌词页。
先完成可用的单场景舞台与歌曲模式切换，再补旧版已有的本地多图场景集。
最小场景能力：选择/替换本地图片、清除、调整背景强度、图片失效时回退到主题底色；
完整本轮目标增加多图选择、手动上一张/下一张、可关闭的自动轮换及重启恢复。
只做一个简单有序图片集合，不做素材市场、时间线、3D、音频分析或可编程场景引擎。
现有 PNG/JPEG 授权、尺寸/像素/解码预算继续有效；多图须另设数量和总缓存上限，
只解码当前与必要的相邻图片，不能把整组 base64 随每次播放快照传送。
只存文件引用和必要设置，不把图片正文写进设置库；丢图允许重选，不阻塞听歌。

5.3 灵动来自连续反馈
列表/舞台切换采用短淡入和轻位移，优先约 180–260ms；按钮反馈约 120–180ms。
场景换图可更舒缓，初始约 800–1600ms；轮换间隔先用约 11 秒，实测后可调整。
这些是起始设计值，不是声称从截图测得，也不是必须精确复制旧实现。
尊重减少动态效果；隐藏、最小化时暂停轮换与非必要动画。禁止常驻无意义漂浮/脉冲。
转场不能拦住下一次操作，切歌与音频播放不等待动画；避免同时解码多图造成停顿。

5.4 尺寸与交互
主窗优先 1180×760，覆盖最小逻辑尺寸 900×620；Mini 参考 420×236、最小 360×220。
沿用当前窗口约束时先核对实际值；截图外框像素不等于逻辑视口。
Windows 缩放 100% / 125% / 150%、最大化/Snap 和 Mini 往返不能遮挡核心控制。
窄屏先收起侧栏/次要信息，不把全页面同比缩小；自动折叠应避免临界宽度反复跳动。
键盘焦点可见、图标按钮有名称、菜单可 Esc 退出；输入框输入不能触发播放快捷键。

5.5 整体玻璃材质与背景显露（2026-09-09 用户追加，当前视觉开发主线）
用户明确否定当前界面的整体观感：顶栏、底栏、设置与切换按钮像零散拼接。
不能把本项缩减为添加几套颜色或给每块卡片加 blur。以统一整窗材质、按钮语言、
间距和信息层级重构视觉，保留已经可靠的播放与数据逻辑；本项优先于继续增加功能。

区分三个概念，禁止用一个透明度同时控制所有层：
a. 背景显露程度：控制图片相对主题底色的可见程度，不降低文字或按钮本身的不透明度。
b. 玻璃通透度：控制顶栏、侧栏、播放台等玻璃表面的底色混合比例。
c. 玻璃雾度：控制表面对身后图片的模糊程度，与图片本身清晰度分开。
界面先提供“清透 / 柔雾 / 磨砂”三种材质预设，加“通透度”滑杆；雾度微调放次级入口。
预设只是少量 token 数值组合，不增加材质插件、主题编辑器或新渲染引擎。
滑杆统一 0–100 的有效整数范围；具体 opacity/blur 映射由视觉验证确定并记入实现记录，
最新用户覆盖要求：玻璃通透度/雾度与旧图片浓度仍为 0–100；背景显露扩展目标为
0–300，0–100 保留已交付映射，100–300 为图像盖过中央内容的沉浸段。
沉浸段不得遮挡设置、播放/暂停、返回和系统窗口控制；中央不可见的动作不得继续盲点触发。
该扩展须同时修改 TS/Rust/存储校验与恢复测试，不能只改滑杆 max；CSS opacity 始终为 0–1。
不把设计起始值伪称为已验收值。CSS opacity 不能超过 1；“更强背景”通过减少遮罩实现。

背景允许比当前实现更充分地显露，高显露端应能欣赏图片细节和原有色彩，
不能再出现滑杆显示 100% 但多层固定暗幕仍把整张图片遮成灰雾的情况。
舞台可以更清透，歌曲列表和控制台保留必要的局部衬底，保证文字/图标可读；
不要依赖低透明度文字来制造玻璃感，也不通过整窗 opacity 淡化所有内容。
提供可预期的恢复默认。保留既有 sceneryIntensity 数据；若新映射改变旧值含义，
明确兼容策略，不静默将用户现有设置转换成完全不同的画面。

玻璃只用于必要的少数层：窗口顶栏、导航、底部播放台、设置面板；共享圆角、
细边缘高光、低强度阴影和色调规则。列表行主要用留白与悬停反馈，不再卡片套卡片。
设置面板是可读性例外：实机若发生底层文字透入，可使用同主题实色衬底，
不强求与低密度外壳相同通透度；这不改变顶栏/侧栏/播放台的可调玻璃要求。
背景层只负责图片，玻璃层负责材质，内容层负责文字和控件，避免多层重复滤镜。
先做应用内背景上的玻璃，不默认开启整窗系统透明或扩大平台权限；模糊不可用时
回退为协调的实体/半透明表面，功能、对比度及焦点不能依赖滤镜成功。
不使用高频动画驱动 blur；记录宽窗和低性能场景的滚动/后台开销，不承诺零成本。

外观草稿实时预览，明确保存后持久化；不能每次拖动都写 SQLite。
取消恢复已提交外观，保存失败保留草稿并可重试；清除图片不清除主题或材质偏好。
主题变化、图片切换和外观草稿并存时，定义优先级：主题提供基础色与默认材质，
用户已保存的材质/强度覆盖默认，当前草稿仅覆盖当前预览；换主题不得暗中丢弃覆盖值。

5.6 顶栏、底栏与切换入口统一设计
最新用户主方向：中央一块主玻璃，顶部/左侧/底部为同材质工具玻璃，不另加右侧栏。
细指针设备可靠近窗口对应边沿滑出工具玻璃；键盘焦点进入时展开，菜单打开时不得收回。
必须提供固定展开开关，触摸/粗指针回退为常驻布局，减少动态时取消位移动画。
中央主玻璃与边缘玻璃共享材质 token，清透/柔雾/磨砂先沿用现有预设，不引入渲染框架。
先交付主玻璃与边缘展开交互，再接入 100–300 中央内容遮盖；分别实机验收，不混淆完成状态。
顶部：消除突兀白色原生标题条与重复标题；品牌仍只用 heni。窗口控制与应用色调协调，
视觉优先级低于音乐内容。Dark 原生窗框仅是当前过渡措施，不等于整体窗框已完成。
2026-09-09 用户明确要求替换顶部黑框：实现常驻、轻薄、同背景的窗口控制栏，
最小化/最大化或还原/关闭只用图标并保留可访问名称；不能随边缘工具栏隐藏。
Mini 合并重复顶部区域、保留返回主窗口；不得直接终止进程绕过正常关闭清理。
若需要一体化自定义标题栏，先验证拖动区域、双击最大化、按钮命中、DPI、边缘缩放、
系统菜单、Snap 和 Mini；不可为了去边框损坏这些桌面行为，也不自制不完整系统替代品。

“歌曲 / 播放舞台”：替换当前右上角孤立的大号分段按钮，设计为工作区内自然、紧凑的
视图控制，与标题/导航对齐；只保留一处主要切换入口，消除正在播放/舞台等同义重复。
允许文字配小图标，但不能只有无法理解的图标；选中态、悬停、焦点、键盘都清楚。
切换只改变呈现，必须保留浏览来源、搜索/滚动和播放连续性，不能另造路由或播放会话。
最新迭代采用图标+短文字双选入口，支持方向键/Home/End；暂不增加右侧滑出面板或
横滑手势，避免与列表横向滚动、三侧工具面板产生竞争；如后续引入须有明确额外价值。

底部播放台：用一组一致的矢量图标、尺寸、触控区域、圆角与反馈重做控制，
禁止使用 ◀ / ▶ 等字体字符拼凑一套按钮，也不混用多种无关的图标风格。
歌曲信息、主播放控制、进度、辅助操作形成清晰层级；播放/暂停为主动作，其他按钮克制。
当前队列入口用图标与必要数量/激活态表达，打开后保持上下文；队列不是又一份歌单管理。
音量入口、静音和滑杆组成一个整体，悬浮/展开不遮挡核心播放控制，数值按需显示。
视觉重做不等于实时音量试听已实现，仍遵守 4.4 的原生预览/提交与静音约束。
播放模式使用清晰的顺序/列表循环/单曲循环/随机语义及当前态提示，不以难猜的图标
反复循环多个隐含状态。可使用就近的小菜单；必须先核对现有 repeatMode 与 shuffle 的
组合规则并记录 UI 动作到命令的映射，不因换图标改变随机或曲尾行为，不删除顺序播放。
所有图标按钮保留名称、提示、键盘焦点与禁用态；最小窗口和 Mini 中仍可操作。

5.7 配色与整窗联动的验收
六套预置配色同时影响背景底色、玻璃色调、边缘、文字、选中/悬停、主动作、进度与音量；
不能只改变色卡和按钮。清理现有绕过 token 的硬编码颜色，但只改相关视觉代码，
不开展无期限通用设计系统重构。主题切换不改图片、曲库、音量或播放状态。
同一测试数据记录：六套配色的无图/亮图/暗图，三材质及滑杆两端/中间值，
宽窗/最小窗/Mini、播放中/暂停/空态、设置打开和键盘焦点。挑代表组合做前后对比，
其余组合逐项记录，不声称一张截图覆盖所有状态。
用户观感反馈是视觉收口依据；数值和测试通过不能代替“整体协调、清晰、好看”的实机复核。

六、工程约束：保留已证明有用的边界

依赖方向：UI → 功能工作流/Hook → 类型化端口 → Tauri 适配器 → Rust 命令
→ 运行时/服务 → 音频引擎、存储、扫描及平台 API。

TypeScript 负责呈现、交互草稿、工作流与边界契约；Rust 是播放、队列、文件授权、
扫描与 SQLite 持久数据的事实来源。不要为学习 TS 将原生可靠性职责搬到前端。
React 不直接读写数据库、递归扫盘或保存音频引擎对象；组件不散落 invoke 字符串。
IPC 输入输出边界校验，区分取消、业务错误和传输错误；内部可信对象不层层重复解析。
有限状态用判别联合与穷尽处理；禁止用 any、随意非空断言、盲目类型转换掩盖问题。

保留现有 App 组合根、feature 模块、端口、Zod、SQLite 迁移及原生播放方案。
只因真实职责和独立变化拆分，不按行数机械拆文件。跨功能流程在 app/workflows 编排。
没有实证需要不引入 Zustand、全局事件总线、路由器、DI 容器、monorepo 或新 UI 框架。
重用简单控件与语义样式，不建设通用设计系统产品。新依赖需写清现有方案的实际缺口。

Hook/异步任务处理卸载、迟到响应、重入、取消、连接替换；订阅和定时器必须回收。
阻塞文件/数据库/探测工作不得卡桌面事件线程；Windows 窗口与 Shell/COM 操作按各自
线程要求处理，不能把所有命令机械包进后台线程。取消通道保持短且可达。
原生音频回调不访问 SQLite、文件系统或做无界等待；不把整首音频解码到前端缓存。

沿用当前条件轮询与局部时钟，先验证正确性和真实开销。不再将“必须 4–5Hz 原生事件”
作为独立完工门槛。只有测得轮询阻塞、载荷/唤醒成本或同步缺口，才写小 ADR 并替换。
任何改动都必须维持曲目身份、seek 顺序及后台恢复一致；不并存两套永久事实来源。

SQLite 变更有版本迁移和失败测试，涉及既有数据先备份。启动数据库失败必须存在
可见、可恢复的错误路径；禁止为启动成功静默重建用户数据库或清空收藏。
不扩大 Tauri CSP/文件权限来省事，不接收任意路径后直接执行 Shell 字符串。
旧版代码、Release、第三方研究目录和用户媒体都保留；测试使用独立数据目录。

七、分阶段执行及交付门槛

V3-0 基线核验与最小风险闭环

—完整 SHA-256—测试数据—结果”记录，不能把旧 exe 的结果归给新源码。
先验证音量恢复、播放基础、启动错误路径及命令行窗口问题；只修复实际阻塞项。
退出条件：有可测试的新基线，重要风险已复现或明确待测；不要在此阶段无限清理代码。

V3-1 先交付用户看得见的完整切片
实现“选择一个歌单 → 播放 → 切舞台 → 返回原歌单位置”的真实闭环。
同时交付固定播放台、深夜主题层级和单图舞台，不接受只有静态设计稿或孤立组件。
覆盖空/有数据/播放中/暂停/错误、宽窗/窄窗；提供相同数据条件的前后截图及切换证据。
退出条件：路径真实可用、播放不中断、没有歌词占位、视觉检查记录具体缺陷与修正。

V3-2 补齐日常使用
完成歌单编辑与队列语义、场景集/强度/轮换、其他现有主题、实时音量试听与保存、
键盘与 Mini 连续性。每次只推进一个纵向切片，同时完成错误处理和针对性测试。
退出条件：对应条目满足下方验收，不以 UI 控件存在代替功能可用。

V3-3 Windows 发布收口
格式/损坏文件/丢文件/重启恢复/长时间播放、DPI/Snap/Mini、无多余控制台窗口，
安装与启动、卸载不误删媒体、依赖与 sidecar 许可证、默认入口/兼容决策逐项验收。
没有设备或工具不能测试的项目，标为待验证并说明复现步骤；不得伪造完成。
只有此阶段必需验收通过，且旧版替代边界获确认，才宣布可替代旧版。

八、验收清单（必须提供证据，不只打勾）

A01 导入：文件/目录/重复/取消/不可读/损坏均有结果，主窗可操作，既有数据无损。
A02 歌单：创建、编辑、加入/移除、播放、删除及重启保留；磁盘媒体不受删除影响。
A03 队列：顺序/随机/循环/重复项/曲尾/移除当前项，状态与真实声音一致。
A04 连续性：歌单—舞台—队列—Mini 往返后，声音、位置、浏览上下文不意外重置。
A05 场景：多图/单图/空图/失效/超限/取消/强度/恢复；减少动态与后台状态正确。
A06 声音：拖动与键盘 seek、连续命令、音量/静音/恢复及失败；无意外满音量。
A07 视觉：六套主题 × 无图/明暗背景，三材质及强度边界；长中文/英文标题、空态、繁忙、错误、无封面；
    核心尺寸及缩放检查，无遮挡、灰雾、焦点丢失、品牌错误和歌词。
A08 稳定性：可恢复启动失败、数据库写失败、迟到异步结果、设备变化；不丢收藏。
A09 性能：记录机器/数据/构建，至少 5,000 项列表操作和 60 分钟播放观察；
    记录导入响应、搜索/滚动卡顿、内存与后台 CPU 趋势，发现回归先定位再优化。
    合成队列载荷测试不是这些性能验收。没有实测不得承诺帧率、零卡顿或无缝播放。
A10 发布：真实新构建启动无伴随控制台；Mini/重启/安装路径验证；记录完整 hash。
A11 外观交互：材质/背景草稿预览、保存/取消/失败/重启、主题与覆盖值优先级；
    顶栏与底栏整体一致，队列/音量/模式入口易懂，视图切换不重置播放或浏览上下文。

自动检查依照仓库真实脚本：pnpm lint、pnpm typecheck、pnpm test、pnpm build；
Rust fmt --check、clippy（警告视为失败）、cargo test，使用当前 Cargo manifest。
新增行为有对应单元/组件或原生测试；故障测试不可只 mock 成成功。
每个切片先跑相关测试，发布前跑完整检查；记录未执行原因和 ignored 测试。
真实声音、窗口、图片观感与安装行为不能仅靠单元测试验收。
