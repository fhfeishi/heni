# 窗口几何：同样是数字，含义不能混用

## 问题

普通窗口、最大化窗口和迷你窗口都有宽高，但三者不能互相替代。此前进入迷你模式时，
直接把最大化客户端尺寸记作普通窗口尺寸；返回时再设置这组尺寸，造成还原和重启越界。

## 直白模型

窗口恢复需要保存两件事：普通窗口的位置/尺寸，以及是否应重新最大化。先暂时退出最大化，
读取普通几何，再改变迷你窗口尺寸。返回时先恢复普通几何，最后按原状态最大化。

另一组区别是逻辑像素与物理像素：TypeScript 界面按逻辑尺寸设计，屏幕位置和原生尺寸
以物理像素处理。边框/标题栏也占空间。不要把截图工具返回的大小直接当作 CSS 视口。

## 最终选择

几何操作留在 Rust 平台层，前端通过 `WindowPort.setMode` 表达“进入/返回”意图。
`WindowSnapshot` 的 `innerWidth`、`innerHeight` 与 `scaleFactor` 是只读事实，React 不维护
第二份窗口恢复坐标，也不根据浏览器 `screen` 猜测系统工作区。

边界修复采用纯函数：输入普通几何、边框尺寸、工作区、缩放后的最小/默认尺寸，输出
可容纳的几何。有效用户尺寸不变；过大的普通窗口缩小到工作区；偏移越界时移回边界；
屏幕小于产品最小尺寸时保留最小布局并把标题栏放回工作区起点，不产生整数下溢。

最大化/最小化状态不做普通窗口修复。暂时退出最大化后若读取失败，尽力恢复原状态。
没有新增全局状态库、Windows 位置数据库或另一套持久化协议。

## 验证与替代方案

纯函数测试覆盖有效几何、旧迷你状态、错误保存的最大化尺寸、负坐标屏幕、100%/125%/
150%/175% 换算、小屏与极端坐标。这些换算测试不能代替真实系统 DPI 测试。
实机还必须走通普通 → 最大化 → 迷你 → 返回 → 还原，以及退出重启。

直接读取 Win32 窗口放置结构也是可行方向，但会引入工作区/屏幕坐标转换与平台专有代码。
当前 Tauri 端口已能表达需要的操作，先用较小方案，并以实际恢复证据验证。

## 阅读与练习

阅读 `src/contracts/window.ts`、`src/features/shell/useWindowMode.ts`、
`src/infrastructure/tauri/windowPort.ts` 和 `src-tauri/src/platform/window.rs`。

练习：为左上角为负坐标、任务栏占用顶部空间的工作区补一个测试。解释为何原点不能写死
为 `(0, 0)`，以及为什么修复前端 Hook 无法解决错误的原生恢复尺寸。
