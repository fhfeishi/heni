# 030 — Promise 不等于后台线程，也不等于结果仍然有效

## 两个不同的问题

前端 `await invoke(...)` 只说明 JavaScript 不会同步等待结果，不保证 Rust 在后台执行。Tauri 的普通同步命令默认在主线程运行；本切片把播放快照、条件读取、播放命令以及设置读写改为 `async` 入口，再把锁等待、媒体加载和 SQLite 操作交给 `spawn_blocking`。[Tauri 命令文档](https://v2.tauri.app/develop/calling-rust/#async-commands)

首批五条入口没有新增命令协议、SQL 或权限。授权仍先于加载，controller 锁仍保持会话与引擎串行一致，音量仍先保存再提交。随后在客户端回归全绿后，把曲库、歌单、旧库检测/导入、扫描和 ffprobe 共 12 条入口也移入阻塞工作池。后台任务失败转成有限错误，不把 panic 内容送到界面。三组领域入口共 9 项 Rust 测试覆盖工作线程身份、领域错误保留和异常映射；测试不证明实机窗口延迟或数据库争用性能。

第二个问题在 TypeScript：异步结果返回时，最初发起它的界面可能已经离开，或者已经切换了端口。Rust 完成了写入，也不代表旧界面还应该跳转或继续播放。

## 曲库连接与一次操作

`useLibrary` 现在把同一端口的可见状态放在一个只读对象中，而不是让多个独立 state 分别过渡。连接 ref 只保存生命周期、操作闸门、读取版本和扫描身份，不复制曲库数据，也不成为全局 store。

- `active`：这个连接是否还存在。卸载或换端口后，旧 Promise、事件和保存下来的 callback 不能更新新界面。
- `mutating`：一次曲库写入是否尚未完成。在 `await` 之前同步设置，阻挡 React 下次渲染前的第二次点击；不把危险操作悄悄排队。
- `revision`：初始快照是否已被一次操作超越。晚到的空库不能覆盖导入结果；与导入文件无关的旧库检测仍可显示，但不能把已经导入成功的状态改回“待导入”。
- `activeScanId`：事件必须属于当前扫描。取消后或收到终止事件后，晚到进度不能把扫描重新变成运行中。

内部 `runLibraryMutation<Value>` 只复用三种真实结果的生命周期：普通 snapshot、重新定位结果和旧库导入 outcome。返回类型跟随操作推导，成功投影仍按用例书写。没有 `any`、动态命令字符串或通用应用 manager。

## 取消不是忽略结果的别名

用户离开时，原生扫描可能还没发出 `started`，前端暂时没有 scan ID。只在 cleanup 取消“已知扫描”是不够的：旧回调晚收到开始事件时，还要通过旧端口请求取消，不能用当前新端口清理旧任务。

取消请求同步去重，失败可以重试；取消失败只在连接仍有效且扫描身份匹配时显示。组件卸载会阻止旧结果进入 React，但不会撤销已经成功的数据库事务，不应向用户承诺这种回滚。

命令结束而终止事件未收到时，界面使用“扫描已结束”，不猜测是完整完成还是用户取消。失败则显示“扫描未完成”，都不保留失效的取消按钮。这两个值只是本地展示状态，不伪造 Rust Channel 事件。

## 取舍与下一步

本切片先建立生命周期和重入保护，通过全量测试后再迁移 12 条曲库 I/O 命令。它们可以在后台等待，但 repository 锁与原事务仍保持数据一致性；取消扫描只操作独立注册表与原子标记，故仍保留短同步入口，不被排到长扫描后面。路径授权先于读取，旧库备份先于事务，扫描批次和最终对账规则没有改动。窗口/Shell 相关入口还要按 Windows 线程语义单独核对；后台入口不是整机无卡顿的证明。

新增 14 项 Hook 回归和 3 项组件检查；真实目录取消、权限失败和旧数据导入仍需独立 Windows 证据，不使用用户数据库做故障注入。

## 阅读路径与练习

1. `src/contracts/library.ts`：Result、只读 snapshot 和扫描事件联合。
2. `src/features/library/useLibrary.ts`：连接身份、同步闸门和异步清理。
3. `src/features/library/useLibrary.test.tsx`：可控 Promise 与晚到事件。
4. `src/features/library/LibraryPanel.tsx`：穷举本地扫描展示状态。
5. `src/infrastructure/tauri/libraryPort.ts`：unknown 校验与真正 IPC 边界。

练习：在取消请求还没返回时让扫描正常完成，随后让取消返回失败。断言已完成的扫描不会被迟到取消错误覆盖，也不会重新出现取消按钮；再测试下一次扫描仍能独立取消。
