# 050 · 歌单列表操作与稳定身份

歌单成员、可见搜索结果、播放队列是三种不同数据。行播放传递媒体 ID，不传当前搜索
结果的下标。App 从完整歌单构建可播放队列后再查找该 ID，避免缺失条目被过滤后播错曲。
队列替换确认也保存该 ID，而不是确认时无条件从零开始。组件不直接控制播放引擎。

PlaylistListeningView 统一承担成员展示、播放、定位和移除。PlaylistItemsEditor 只负责
从曲库或来源歌单添加引用，不再重复展示另一套成员管理列表。来源歌单顺序保留，目标
已有成员由共享候选投影排除；底层既有歌单接口负责持久化，不新增数据库或命令体系。

定位先清除搜索，再在提交后的 effect 中滚动和聚焦当前行。普通播放快照变化不触发
自动滚动，避免用户浏览时被拉走。搜索改变清空选择，全选只包含当前结果，移除时还与
最新成员取交集。失败保留选择，成功才清空；ref 锁保护同一提交被连续触发。

歌单移除不是文件删除，也不是从播放队列移除。保持三者的边界，才能让编辑歌单不打断
正在播放的音乐。当前原生窗口视觉和真实双击手感仍需实机验收。
