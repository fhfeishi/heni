# Heni 全景主题外壳设计

日期：2026-07-17
状态：视觉方向已确认，等待设计文档复核
目标分支：`codex/studio-listening-console`

## 1. 背景与已确认决策

用户最终选择 B「全景背景画布」，并确认品牌字标只使用小写 `heni`，不再展示圆形大写 `H` 或大写 `HENI`。

本轮优化同时解决两个已经核实的问题：

1. 常用主目录仍停留在 `codex/player-usability-upgrade`，上轮 UI 只存在于 `codex/studio-listening-console` 工作树，因此主目录构建出的 Release 仍带白色系统标题栏。
2. 新分支虽然已经使用无标题栏窗口，但曲库模式对背景叠加了过重的深色遮罩，并让顶栏、曲库、侧栏、底栏复用过于接近的灰褐色玻璃面，导致主题色、背景图片和功能层级都被压平。

## 2. 目标

- 背景图片真正覆盖整个 Flutter 窗口，包括标题栏、侧栏、内容区和底部播放坞。
- 最外层使用当前主题色合成，不再出现与播放器割裂的白色系统标题栏或纯黑外壳。
- 减少大圆角面板层层嵌套，建立一套更成熟的桌面播放器层级。
- 保持文字、歌曲列表与播放控件在任意内置主题和任意背景图上清晰可用。
- 保持现有音频播放链路，不引入重采样、响度处理、均衡器或格式转换。
- 保留已有的最小窗口、响应式侧栏、播放列表定位当前曲目、打开文件位置等实用功能。
- 把最终更新真正落到主目录 Release，并验证启动的二进制来自同一提交。

## 3. 非目标

- 不增加歌词展示。
- 不恢复“导出 FLAC”或任何有损转无损功能。
- 不增加频谱、可视化或常驻动画来占用播放资源。
- 不根据背景图片自动改写用户选择的主题；背景只参与氛围，主题选择仍是视觉语义的唯一来源。
- 不在本轮重构音频引擎或媒体扫描架构。

## 4. 视觉系统

### 4.1 全景背景

`GlobalSceneryBackdrop` 继续作为最底层，但改为更清晰的双模式处理：

- 播放页：图片保持较高可辨识度，建议模糊 8–12、饱和度 0.78–0.88、主题遮罩 0.26–0.34。
- 曲库页：为歌曲列表提高稳定对比度，建议模糊 14–18、饱和度 0.66–0.76、主题遮罩 0.40–0.50。
- 背景切换使用 700–900 ms 交叉淡化，不缩放或平移画面。
- 图片缺失、无法读取或列表为空时，回退到由 `seed → surface → glow` 生成的主题渐变，不显示纯黑空底。

现有曲库模式的 0.68 深色覆盖和上层 0.30 二次覆盖需要降低，并合并为可追踪的主题令牌，避免多层透明度相乘后变成灰泥效果。

### 4.2 主题合成

新增或集中一组外壳语义颜色，而不是在各个组件中散落 `Colors.black` 与 `Colors.white`：

- `shellCanvas`：全窗口主题薄膜。
- `shellChrome`：顶栏与窗口按钮所在材质。
- `shellRail`：侧栏材质。
- `shellContent`：曲库/播放舞台材质。
- `shellDock`：底部播放坞材质。
- `shellBorder`：由 `seed`、白色高光与 `accent` 合成的细边界。
- `shellHover`、`shellPressed`、`shellSelected`：统一交互状态。

这些颜色由当前 `HeniPalette` 派生。背景图不能替换主题色，只能从透明区域透出。所有文本与图标仍按背景合成后的实际亮度保证至少可读对比度。

### 4.3 最外层窗口

- Windows 继续使用 captionless native frame，保留系统缩放、阴影、贴靠、最小化、最大化与关闭行为。
- Flutter 内容延伸到窗口四边；最外层只保留 1 px 主题渐变描边和轻微内高光，不再放置一张独立的“大卡片”模拟窗口。
- 常规状态使用约 14 px 的视觉圆角；最大化时去除外边距和视觉圆角，避免屏幕边缘出现缝隙。
- 标题栏不是独立胶囊，而是覆盖在全景背景上的一条连续玻璃层，与侧栏和内容区通过细分隔线建立关系。

### 4.4 品牌字标

- 顶栏左侧仅展示小写 `heni`。
- 移除圆形大写 `H` 徽标和大写 `HENI` 组合。
- 字标建议使用 17–18 px、700 字重、轻微字距，不做发光动画。
- Windows 原生资源图标同步改为小写 `heni` 的简化字标版本；需要针对 16/24/32/48/256 px 做光学尺寸检查，避免任务栏小尺寸糊成色块。

## 5. 布局与组件

### 5.1 顶栏

- 左：`heni` 字标和可拖动区域。
- 中：统一搜索框；窄宽度下只保留搜索图标，点击后在顶栏内展开。
- 右：主题入口、设置入口、最小化、最大化/还原、关闭。
- 关闭按钮只在悬停/按下时使用红色；其他窗口按钮使用主题悬停色。
- 空白区域支持拖动，双击切换最大化；交互控件自身不得触发窗口拖动。

### 5.2 侧栏

- 展开模式显示图标和文字，作为桌面宽度下的默认模式。
- 紧凑模式只显示图标和提示，用于用户手动选择或窗口变窄后的自动降级。
- 宽度低于自动阈值时强制紧凑；恢复到阈值以上至少 32 px 后再自动恢复用户偏好的展开模式，避免拖动窗口时来回闪烁。
- 侧栏直接铺在背景玻璃层上，不再包裹完整大圆角卡片。

### 5.3 主内容

- 曲库只保留一个主要内容表面，标题区与歌曲行通过间距、细线和状态色区分。
- 减少每一行的独立轮廓；悬停只增加轻微主题染色，当前播放行增加左侧细标记和一次短暂定位闪光。
- 歌曲名称、路径/格式、时长和更多操作保持稳定列宽；窄宽度时路径/格式信息优先隐藏，歌曲名使用省略号。

### 5.4 底部播放坞

- 播放坞横跨窗口底部，背景图片仍可从其材质下透出。
- 左侧为封面、歌曲名和简短音频信息；中间为播放控制与进度；右侧为队列、播放模式和音量。
- 进度条始终位于 `Expanded` 的有界区域，左右时间标签使用固定最小宽度，窗口拖动时不得与总时长重叠。
- 窄宽度依次隐藏次要音频信息、上一首按钮和非关键工具；播放/暂停、进度、音量和队列始终可达。

## 6. 关键交互

### 6.1 当前播放列表定位

- 当前播放列表弹窗提供常驻“定位当前播放”按钮。
- 有当前曲目时，点击后滚动至对应行并触发约 900 ms 的主题色定位闪光。
- 当前曲目不在当前筛选结果中时，按钮提示原因，不悄悄改变用户筛选条件。
- 无当前曲目时按钮禁用，并通过 Tooltip 解释状态。

### 6.2 音量

- 移除当前不协调的展开方式，改为从扬声器按钮上方弹出的紧凑音量浮层。
- 浮层包含静音按钮、水平滑杆和整数百分比；拖动、点击轨道和鼠标滚轮都可调节。
- 音量变化即时写入引擎，交互结束后再持久化，避免高频磁盘写入。
- 静音后保留上次非零音量，再次点击恢复。

### 6.3 动效

- 悬停/按下：120–180 ms。
- 侧栏与布局切换：220–300 ms。
- 背景切换：700–900 ms。
- 当前曲目定位闪光：约 900 ms，只播放一次。
- 遵循系统“减少动态效果”设置；禁用后改为即时状态切换。

## 7. 响应式与窗口约束

- 原生窗口最小逻辑尺寸保持 900 × 620；高 DPI 下按系统比例转换为物理像素。
- Flutter 层仍需按实际约束布局，不能只依赖原生最小尺寸作为防线。
- 建议断点：
  - `>= 1180`：优先展开侧栏、完整底栏。
  - `900–1179`：按用户偏好或空间强制紧凑侧栏，底栏逐级压缩。
  - `< 900`：正常拖动路径不应到达；测试中仍需保证无 overflow。
- 最大化时外框与屏幕边缘贴合；还原后恢复主题描边和视觉圆角。

## 8. 架构与数据流

外壳层级保持单向、可测试：

1. `activePaletteProvider` 提供用户选择的 `HeniPalette`。
2. 主题合成函数生成不可变的外壳语义颜色。
3. `PlayerScreen` 只把语义颜色和模式传给背景、顶栏、侧栏、内容与底栏。
4. 各组件不得自行再次叠加不透明黑色来“修正”对比度。
5. 背景图片路径仍由 `sceneryImagePathsProvider` 提供；无效路径在背景层过滤并走主题回退。
6. 原生窗口状态由 `heniWindowControllerProvider` 提供，最大化状态决定外框边距与圆角。

预计主要涉及：

- `lib/design/app_theme.dart`
- `lib/features/player/presentation/global_scenery_backdrop.dart`
- `lib/features/player/presentation/player_window_chrome.dart`
- `lib/features/player/presentation/player_screen.dart`
- `windows/runner/resources/app_icon.ico` 及其源文件（若仓库已有源资产）

## 9. 错误与降级

- 背景图片不可读：跳过该路径并回退到主题渐变，不中断播放器。
- 所有背景都不可读：保持主题渐变与完整控件，不显示空白窗口。
- 原生窗口方法调用失败：记录状态并保持 Flutter 界面可用；关闭按钮仍需要明确失败反馈，不能静默无响应。
- 音频探测失败：底栏只隐藏未知格式信息，不影响播放控制。
- 当前曲目定位目标消失：弹窗显示轻量状态提示，不抛出滚动异常。

## 10. 测试与验收

### 自动测试

- 主题语义颜色在所有内置调色板下满足透明度、前景可读性和状态差异要求。
- 顶栏只出现小写 `heni`，不再渲染圆形 `H` 或大写 `HENI`。
- 背景缺失时渲染主题渐变。
- 最大化/还原状态切换外框边距和圆角。
- 900、1180、1360 等关键宽度下侧栏与底栏切换正确，无布局 overflow。
- 进度条时间标签在持续调整宽度时不重叠。
- 播放列表定位与音量持久化继续通过现有测试。

### Release 验收

1. 在 `codex/studio-listening-console` 完成测试、格式检查与 Windows Release 构建。
2. 启动该工作树的精确 Release 路径，核实无系统标题栏、背景铺满、`heni` 字标和窗口按钮交互。
3. 将完成提交快进应用到主目录分支 `codex/player-usability-upgrade`。
4. 在主目录重新构建 Release，而不是复制旧二进制。
5. 对比主目录和功能分支的 Git 提交、可执行文件时间戳与 SHA-256，确认交付来自同一代码。
6. 启动主目录精确 Release 路径并截图复核；只有这一步通过后，才声称更新已应用。
7. 更新项目 Strata 启动文档与发布记录，提交并推送远端。

## 11. 完成标准

- 用户常用的主目录 Release 不再显示白色系统标题栏。
- 背景图片从窗口最外层贯穿到顶栏和底栏，并在曲库页仍清晰可辨。
- 主题切换会同时影响外边界、玻璃染色、交互状态和进度条。
- 顶栏只展示小写 `heni`。
- UI 不再由多个同色大圆角卡片堆叠而成。
- 最小尺寸、侧栏自动切换、进度条、当前曲目定位、音量和窗口按钮交互合理。
- 不出现歌词入口和 FLAC 导出入口。
- 自动测试、静态检查、Release 构建和主目录实机启动验证全部通过。
